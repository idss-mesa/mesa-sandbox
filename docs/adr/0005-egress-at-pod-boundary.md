# ADR-0005: Egress is enforced at the pod boundary

Status: accepted. Sources: `docs/research/runtime-isolation.md`, `prior-art-platforms.md`, `cyverse-vice.md`.

## Context
Claude Code's bubblewrap sandbox, Codex's network proxy, Cursor's sandbox and GitHub Copilot's firewall all explicitly exclude MCP servers and hooks. VICE bundles several MCP servers. `vice-operator` already emits a namespace default-deny and a per-analysis egress NetworkPolicy with `DisableInternet`, `AllowedCIDRs` and `PodExceptions`.

## Decision
Egress classes N0–N3 (ADR-0002) are implemented as per-analysis NetworkPolicies generated by the launcher (extend the operator's flags into per-profile fields) plus the egress-proxy sidecar (ADR-0003) as the only permitted route, enforcing an SNI/FQDN, method and path allowlist. In-harness network settings (`sandbox.network.allowedDomains`, Codex `[features.network_proxy]`, Cursor `sandbox.json`) are configured for defense in depth only. Approving a new domain from the approval inbox (ADR-0014) hot-reloads the proxy allowlist without restarting the pod.

## Consequences
CNI support for FQDN policies (Cilium `toFQDNs`) is optional; the proxy carries the domain logic. Cluster metadata endpoints are blocked by default.
