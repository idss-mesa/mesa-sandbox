### Iron Bank reproducible builds (docs-ironbank.dso.mil/hardening/reproducible-builds/, fetched 2026-09-06)

"Reproducible builds in the context of container images mean that building the same Dockerfile with the same inputs always yields an identical container image digest (SHA)." With the `REPRODUCIBLE_BUILDS` variable the pipeline sets `SOURCE_DATE_EPOCH` and `org.opencontainers.image.created` to `CI_COMMIT_TIMESTAMP`, drops the `mil.dso.ironbank.ci.id` label, and writes new attestations only when VAT findings or the Syft version change. Guidance: prefer minimal/distroless bases that change only when versioned; replace dynamic commands (`date +%s`) with `SOURCE_DATE_EPOCH`; pin pip with `--require-hashes` and clean caches; clear apt caches, logs and temp files; remove npm caches (`/root/.npm`, `/tmp/node-compile-cache`); normalise `/etc/shadow` "days since password change"; use `diffoci` to debug digest differences; rely on `org.opencontainers.image.source`/`revision` for traceability.
