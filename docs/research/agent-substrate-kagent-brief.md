# Agent Substrate, kagent AgentHarness/Harness, OpenClaw, NemoClaw/OpenShell — technical brief

Date: 2026-09-06. Read-only web research against primary sources (repos, docs, release pages). Every specific name below was seen in a fetched source; URLs are given inline.

## 1. What Agent Substrate is

Agent Substrate ("ate", https://github.com/agent-substrate/substrate) maps many stateful "actors" (agents, sandboxes, MCP servers) onto a smaller pool of pre-warmed worker Pods. Idle actors are checkpointed (process memory + rootfs delta + durable volume) to object storage and restored on demand onto any free worker; a substrate-aware router resumes an actor when traffic arrives. It runs its own gRPC control plane and database beside Kubernetes and uses Kubernetes only for worker Pods, nodes, CRDs and RBAC. Sandbox classes: gVisor (`runsc`, default) and micro-VM (Kata + Cloud Hypervisor). It is "not an SDK for building agents".

- Maintainers: 16 Google (incl. thockin, BenTheElder, msau42, rakyll) and 2 Solo.io ([MAINTAINERS.md](https://github.com/agent-substrate/substrate/blob/main/MAINTAINERS.md)); "not an officially supported Google product"; Google CLA. Announced at Google Cloud Next '26 (2026-05-20) as pairing Agent Sandbox's runtime/snapshotting with a minimal control plane.
- License: Apache-2.0.
- Releases: upstream has exactly one tag, **v0.0.0 (2026-05-19)**, no Helm chart (kustomize + `ko`). The "0.0.8" used by the js2-substrate design is a release of the **kagent fork** `kagent-dev/substrate`, which adds Helm charts and publishes `ghcr.io/kagent-dev/substrate/*`; fork releases run v0.0.3–v0.0.6 (2026-06-10), v0.0.8 (2026-07-02), … v0.0.26 (2026-09-06). Upstream README: APIs "almost guaranteed to change", "not ready for production use".
- Kubernetes: latest stable and previous minor. Upstream default (mTLS) install needs beta `certificates.k8s.io/v1beta1` PodCertificateRequest/ClusterTrustBundle APIs and feature gates (GKE 1.36 with betas or 1.37+); the fork's `auth.mode: jwt` needs only projected SA tokens, which is what makes k3s feasible. Nodes must carry `ate.dev/substrate-version` or they host no workers. The "8 vCPU / 16 GB minimum" is the kagent blog's kind-on-one-host guidance, not a project spec.

## 2. Components, APIs, lifecycle, snapshots

- Binaries: `ateapi` (gRPC control plane; PostgreSQL upstream since PR #940, Valkey in the 0.0.8-era fork), `atecontroller` (WorkerPool → Deployment + per-pool ingress-only NetworkPolicy), `atelet` (DaemonSet: pulls images, drives ateom, streams snapshots to GCS/S3; runs as root with all caps dropped, hostPath `/var/lib/ateom-gvisor`, hostPorts 8085/9090), `ateom-gvisor` / `ateom-microvm` (per-worker herder: `runsc create/start/checkpoint/restore`, `atunnel` on 443, per-actor veth via nftables), `atenet` (CoreDNS + Envoy/agentgateway router + egress gateway), `podcertcontroller`, `kubectl-ate`, `rustfs` (in-cluster S3 for snapshots).
- CRDs `ate.dev/v1alpha1`: `WorkerPool` (`replicas`, `workerImage` upstream / `ateomImage` in the fork, `sandboxClass`, pod template, resources define per-actor capacity: "an actor occupies its whole worker"), `SandboxConfig` (cluster-scoped; runsc/kata assets by arch with sha256; shipped `gvisor-default`), `CSIDriverConfig`. `ActorTemplate` is **not** a CRD upstream (ate-api record via `kubectl ate`); the fork had it as a CRD at v0.0.8 and has since dropped it.
- ate-api records: `Atespace`, `ActorTemplate` (containers with digest-pinned image, literal `env` only — `valueFrom` unsupported upstream, max 32 vars per kagent's translator; volumes `durableDir` | `externalVolumeTemplate` | `systemInfo` | `image`; `snapshotsConfig` FULL/DATA, resume COLD_BOOT/GOLDEN; `sandboxConfig`; default caps `AUDIT_WRITE, KILL, NET_BIND_SERVICE`), `Actor`, `Tag`, `Worker`, `EgressPolicy` (hostname/CIDR/all rules with `inject_static_headers` and `credential_uri`). RPCs: Create/Resume/Suspend/Pause/Delete actor, tags, workers (`DrainWorker`), atespaces, egress policies; `ActorIdentity.MintJWT/MintCert`.
- Lifecycle: `ActorTemplate` creation boots a golden actor and takes the Golden Snapshot; `CreateActor` → SUSPENDED; `ResumeActor` (explicit or on traffic) → RUNNING (`runsc restore -background -direct -detach`); `SuspendActor` → checkpoint + upload + wipe worker ("an actor owns one snapshot at a time"); `PauseActor` keeps a node-local checkpoint. **Nothing auto-suspends idle actors** (issues #483, #707 open); snapshots restore only on the sandbox version that wrote them.
- Snapshots: `<location>/atespaces/<a>/actors/<uid>/snapshots/<name>` (manifest + memory image + durable tar), parallel zstd, sparse extents; gVisor templates allow **one** `DurableDir`. Env values are literal strings in the DB and in every Full snapshot; the threat model (T-11, T-23, T-29) therefore routes credentials through egress header injection (`substrate-secret://`) instead of into the sandbox. Snapshot encryption/signing is recommended, not implemented.

## 3. Isolation

- gVisor: `runsc --cpu-num-from-quota` with `-allow-connected-on-save`; `pause` container holds namespaces. Worker pods are not `privileged` since PR #496 (2026-07-22) but run as root with `drop: ALL` plus `NET_ADMIN, SYS_ADMIN, SYS_CHROOT, SYS_PTRACE, SETUID, SETGID, SETPCAP, DAC_OVERRIDE, FOWNER, CHOWN, MKNOD, NET_RAW, SETFCAP`, **AppArmor and seccomp Unconfined**, hostPath, cgroup v2; microvm adds `/dev/kvm` and `/dev/net/tun`. PSA baseline/restricted reject them. User namespaces are not used (recommended as future work; `hostUsers: false` "can break cgroup delegation", issue #627).
- Threat model ([docs/threat-model.md](https://github.com/agent-substrate/substrate/blob/main/docs/threat-model.md)): "little to no security hardening at this time"; do not co-locate control plane with sandboxes (T-06); default-deny (T-16/17); block the K8s API from actors (T-22). Authn exists (mTLS + JWT); **authz does not** ("only configure providers whose users should have full control of the entire control plane").
- Network: per-pool NetworkPolicy is ingress-only; egress default-deny must be your own. Egress control is opt-in via `atenet-egress` (mTLS + CONNECT per actor identity `spiffe://substrate-actor.local/...`), per-actor `EgressPolicy`, experimental SDS-mint MITM; non-HTTP egress e2e is open (#1017).
- Secrets: upstream has no in-sandbox secret projection; the fork/kagent path resolves `valueFrom.secretKeyRef` at resume (needs ate-api to read Secrets in the harness namespace).
- GPU: "temporarily unsupported" — `nvidia.com/gpu` on a pool only places the worker; CDI/`--nvproxy` was merged (#502) then pulled (#752); CUDA-context checkpoint fails (#779); microvm GPU passthrough not started (#762). gVisor nvproxy itself supports compute/utility/graphics only (no DRM).
- Interactive ports: HTTP(S) only via `Host: <actor>.<atespace>.actors.resources.substrate.ate.dev` on the router (port 80 → actor port 80), plus HTTP-only `CONNECT` tunnels; **WebSockets work since PR #1218 (2026-08-26)** with a Jupyter demo (`demos/jupyter`); Envoy route timeout defaults to 10 s (`--route-timeout`). **No exec/attach/SSH** (#185). `rakyll/ate-env` is a small in-actor HTTP tool server; `themsquared/substrate-scope` is a visualizer/autoscaler.

## 4. Long-running / durable jobs

Actors run as long as they stay RUNNING and pin a whole worker; open TCP connections cannot be safely suspended (#465); a worker dying mid-run loses state since the last checkpoint; rolling upgrades drain one node at a time. Capacity = warm `WorkerPool.replicas`; over-subscription parks requests for `--parked-request-budget` (5 s); HPA demo exists; worker autoscaling, storage tiering, incremental snapshots are roadmap.

## 5. kagent integration

- kagent (CNCF Sandbox since 2025-05-22, Apache-2.0): latest **v0.10.0 (2026-09-04)**; substrate support since v0.9.7 (2026-06-11); v0.9.9 is the documented minimum for `AgentHarness` on substrate; v0.10.0 bumps the fork chart to 0.0.8, adds the ACP shim, `SandboxAgent` BYO/Python runtimes, `durableDir` session state, a Claude ACP sandbox target. Pairing caveat: the blog pins substrate 0.0.8 to kagent 0.10.0-beta6 and says 0.0.9 broke the wire format, yet v0.10.0's `go.mod` uses fork v0.0.9 and `main` v0.0.25 — verify the exact chart pairing per tag.
- Direction: "move away from our current Deployment-based runtime and fully embrace Agent Substrate"; `main` replaces `AgentHarness` with `kagent.dev/v1alpha3` **`Harness`** (`spec.kagent|codex|claude|byo`, `workload.image@sha256`, `env[].credentialRef`, `substrate.{workerPoolRef, snapshotPolicy.location}`, status `capabilities{approvals, resume, checkpoint, mcpInjection}`) with Go adapters for Claude and Codex; OpenClaw/Hermes are not in that enum.
- `AgentHarness` v1alpha2 at v0.10.0: `spec.backend: openclaw|hermes`, `spec.substrate{workerPoolRef, snapshotsConfig.location ^gs://, workloadImage}`, `image`, `env[]`, `modelConfigRef`, `channels[]` (telegram/slack). **Image contract:** the generated ActorTemplate startup script base64-decodes a kagent-generated `openclaw.json` and **overwrites `~/.openclaw/openclaw.json`** (no merge), runs `openclaw gateway run --port 18789 --allow-unconfigured`, then `acp-shim --listen :80 -- openclaw acp`. This answers js2-substrate's open question #1 in the bad case: MCP servers baked into a harness image are lost; they must come through kagent resources.
- How kagent talks to substrate: Helm `controller.substrate.{enabled, ateApiEndpoint, ateApiInsecure, ateApiTokenFile, atenetRouterURL, defaultWorkerPool}` and `substrateWorkerPool.*`; projected SA JWT auth. Other CRDs: `Agent`, `SandboxAgent`, `ModelConfig` (providers incl. Ollama/OpenAI-compatible), `RemoteMCPServer`, `MCPServer` (kmcp). HITL = `requireApproval` + `ask_user` over A2A `input_required`; ACP `session/request_permission` for harnesses. agentgateway is the LLM/MCP proxy option and an alternative atenet dataplane.

## 6. OpenClaw; NemoClaw / OpenShell

- OpenClaw (https://github.com/openclaw/openclaw, MIT, OpenClaw Foundation; v2026.9.2): one long-lived Gateway daemon (`127.0.0.1:18789`, WebSocket JSON), single JSON5 config `~/.openclaw/openclaw.json` (`gateway`, `channels`, `tools`, `plugins`, `mcp.servers`, `models.providers`, `agents.{defaults,entries}`, `secrets`, `$include`), `tools.exec.mode: deny|allowlist|ask|auto|full` with approvals persisted in SQLite, sandboxing off by default (`agents.defaults.sandbox.mode`, backends docker|podman|ssh|openshell), `openclaw acp` stdio bridge, ACPX runs Claude Code/Codex/Gemini as external harnesses.
- NVIDIA OpenShell (https://github.com/NVIDIA/OpenShell, Apache-2.0, alpha, v0.0.116): gateway + per-sandbox supervisor; YAML policies for filesystem (Landlock), process (seccomp, run-as user), network (L7 proxy, method/path, hot reload), inference routing with credential injection; drivers Docker, Podman, MicroVM, **Kubernetes (requires kubernetes-sigs/agent-sandbox CRDs)**; experimental GPU. NemoClaw (https://github.com/NVIDIA/NemoClaw, Apache-2.0, alpha): reference stack running OpenClaw/Hermes inside OpenShell sandboxes (Docker containers, Landlock + seccomp + netns, deny-by-default egress). kagent v0.10.0 dropped its `nemoclaw` backend and `runtime: openshell`.

## 7. Comparison

- kubernetes-sigs/agent-sandbox (SIG Apps, Apache-2.0, **v1.0.0 2026-08-28, v1.0.1 2026-09-03**): `Sandbox` (agents.x-k8s.io/v1beta1: `podTemplate`, `volumeClaimTemplates`, `service`, `shutdownTime`/`shutdownPolicy Delete|Retain` (default Retain), `operatingMode Running|Suspended`) plus `SandboxTemplate/SandboxClaim/SandboxWarmPool`; isolation via `RuntimeClass`; `sandboxd` (REST fs + gRPC process service); optional Go `sandbox-router` with path routing and session-cookie auth; suspend = delete pod, keep PVC; memory snapshots are a separate KEP. 1 Sandbox : 1 Pod, Kubernetes-native, stable API, CNCF-hosted. Substrate = N actors : M pods with memory checkpoints, own DB, unstable v0.0.x.
- E2B (Firecracker, Nomad/Terraform self-host, no GPU), Daytona (closed-source since June 2026), microsandbox (libkrun, local-first, no GPU) — not Kubernetes-native.

## 8. Assessment for CyVerse VICE

Each VICE analysis *could* be a Substrate actor for HTTP/WebSocket apps (the Jupyter demo proves it), but: HTTP-only ingress and no exec; long-running interactive sessions pin whole workers and cannot be suspended while sockets are open; one `DurableDir` with multi-GB snapshots per suspend; GPUs disabled; worker pods need 13 caps and Unconfined seccomp/AppArmor; no ate-api authorization; APIs change without notice; fork/kagent versions must move in lockstep. **Recommended shape:** keep VICE analyses as they are and run headless agents as a separate tier (kagent `Harness`/`SandboxAgent` on a Substrate `WorkerPool`, or, more conservatively today, agent-sandbox `Sandbox` pods), sharing data through a CSI volume or iRODS/HTTP APIs with credentials injected at egress. Watch: lazy/self-suspend (#707/#483), suspend-safe networking (#465), device/GPU API (#752).
